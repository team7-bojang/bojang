# 랜딩페이지 설계

> 작성일: 2026-06-23 · 대상: `frontend` · 서비스: 보장zip

## 목적

서비스(보장zip)의 첫 진입점이 될 랜딩페이지를 추가한다. 방문자에게 (1) 서비스가 무엇을
해주는지(놓친 보장·보험금·특약 탐색), (2) 어떻게 동작하는지, (3) 어떤 질문을 던질 수 있는지,
(4) 왜 믿을 만한지를 한 페이지에서 보여주고 핵심 행동(분석 시작)으로 유도한다.

## 결정 사항 요약

- **라우팅**: `/` → 새 `LandingPage`. 기존 보험 등록+상황입력 화면(`HomePage`)은 `/home`으로 이동.
  랜딩의 모든 CTA는 `/home`으로 연결.
- **색상**: 기존 디자인 토큰만 사용(`--color-primary` 틸 `#0d6e66` 계열). 원본 목업의 파랑은
  `primary`로 매핑. 새 색상 도입 금지.
- **히어로 애니메이션 충실도**: "양식화된 미니 UI 재현" — 실제 페이지 컴포넌트를 재사용하지 않고
  단순화된 미니 목업을 그려 단계 전환을 연출한다.
- **3페이지 콘텐츠**: 핵심 가치 3가지 카드만. (최종 CTA 배너·FAQ는 범위 제외)

## 디렉터리 / 파일 구조

```text
frontend/src/
  pages/LandingPage.tsx                         # 랜딩 페이지 조립
  features/landing/
    components/
      HeroSection.tsx                           # 1페이지: 히어로
      RotatingHeadline.tsx                      # 제목 둘째 줄 로테이트
      HeroFlowAnimation.tsx                     # 히어로 우측 미니 UI 흐름 애니메이션
      ScenarioSection.tsx                       # 2페이지: 시나리오 마퀴
      ScenarioCard.tsx                          # 시나리오 카드
      ValueSection.tsx                          # 3페이지: 핵심 가치 3가지
      LandingFooter.tsx                         # 하단 footer
    data/
      scenarios.ts                              # 시나리오 카드 데이터(텍스트 분리)
```

라우팅 변경은 `frontend/src/App.tsx`, 기존 `HomePage` 내부의 `navigate('/cases/...')` 흐름은
그대로 두되 진입 경로만 `/home`으로 변경.

## 컴포넌트 명세

### LandingPage (pages/LandingPage.tsx)
- 역할: `AppHeader` + `HeroSection` + `ScenarioSection` + `ValueSection` + `LandingFooter`를
  세로로 조립. 페이지 배경/섹션 간 여백 담당.
- 의존: 하위 섹션 컴포넌트, `AppHeader`.

### HeroSection
- 좌측: 배지("AI가 찾아주는 내 보험의 숨은 혜택") + 제목 첫 줄("이미 낸 보험료") +
  `RotatingHeadline` + 보조 카피("어떤 도움이 필요하신가요?") + CTA 버튼 2개.
- CTA: "청구가능보험 확인하기", "추가보장찾기 시작하기" — 둘 다 `/home`으로 이동(react-router `Link`/`navigate`).
- 우측: `HeroFlowAnimation`.
- 반응형: `lg` 이상 2열 그리드, 그 이하 1열(애니메이션은 하단 또는 축소).

### RotatingHeadline
- 입력: 문구 배열(기본값 내장) — `['놓친 보장이 있는지', '받을 수 있는 보험금이 있는지', '청구 가능한 특약이 있는지']`.
- 동작: 약 2.5초 간격으로 순환, framer-motion `AnimatePresence`로 페이드+슬라이드 전환.
- 접근성: `prefers-reduced-motion`이면 전환 없이 첫 문구 고정(또는 즉시 교체).
- 의존: framer-motion.

### HeroFlowAnimation
- 역할: 서비스 동작 흐름을 미니 UI로 재현. **결과 화면이 이 서비스의 핵심**이므로 두 결과 모드를
  사용자가 직접 골라 볼 수 있게 한다.
- **상단 탭 2개**로 케이스를 전환한다:
  - **청구가능 (Case1)**: 홈 → 상황 확인 → 분석 결과(금액)
  - **추가보장찾기 (Case2)**: 홈 → 상황 확인 → 분석 결과(그래프)
- 선택된 케이스의 3단계를 자동 순환(반복)하며, **탭을 바꾸면 그 케이스 흐름이 "홈"부터 다시
  시작**한다. 기본 선택은 Case1.
- 단계 내용:
  1. **홈** — 챗봇 입력 영역에 사용자가 질문을 타이핑하는 **타자기 효과**. (질문 텍스트는 케이스별로 다름)
  2. **상황 확인** — 입력 내용이 요약된 확인 카드.
  3. **분석 결과**:
     - Case1 → 실제 `AmountTiles`의 룰렛 느낌을 살린 **금액 카운트업**(예: 0 → 612,000원) +
       "청구 가능 보장 N건" + 청구 가능 특약 1~2줄. (무거운 롤링 타일 대신 숫자 카운트업으로 대체)
     - Case2 → 실제 `CoverageGrowthChart`처럼 "현재 / 조건 충족 시" **두 막대가 차오르는
       그래프**(예상 막대 상단에 추가분 강조 색) + 금액 라벨 + "더 받을 수 있어요" 카피.
- 결과 단계는 연출을 보여줄 수 있게 입력/확인 단계보다 약간 더 길게 머문다.
- 실제 페이지 컴포넌트를 재사용하지 않고 단순화된 마크업으로 그린다(독립적, 가벼움).
  단, 결과 표현은 실제 화면의 색·구조(금액 강조 색, 막대 색 `#bfe5df`/`#18c9b5`)를 따라
  너무 단순해 보이지 않게 한다.
- 접근성: `prefers-reduced-motion`이면 자동 순환 없이 선택된 케이스의 결과 단계를 정지 표시
  (카운트업·막대 애니메이션은 즉시 완료 상태). 탭은 항상 클릭 가능.
- 의존: framer-motion, 내부 상태(선택 케이스, 현재 단계 인덱스, 타이핑 진행, 카운트업 값).

### ScenarioSection + ScenarioCard
- 상단 카피: 예) "이런 상황, 청구 가능할까요?" + 보조 문구.
- 시나리오 카드들이 가로로 **무한 자동 스크롤(마퀴)** — 천천히 좌측 이동하며 끊김 없이 순환.
  hover 시 일시정지.
- 카드 내용: 질문형 시나리오(예: "허리디스크로 입원했어요. 청구가 가능할까요?"). 원본 목업의
  후기 카드 레이아웃을 차용하되 후기 대신 질문 텍스트.
- 데이터: `data/scenarios.ts`에 배열로 분리(코드에 하드코딩하지 않음).
- 마퀴는 CSS keyframe(`index.css`에 추가) 또는 framer-motion으로 구현. 무한 루프를 위해 카드
  목록을 2배 복제해 이어붙인다.
- 접근성: `prefers-reduced-motion`이면 자동 스크롤 정지(정적 가로 스크롤로 노출).

### ValueSection
- 카드 3개:
  1. **약관 원문 근거** — 분석 결과를 약관 원문과 함께 제시.
  2. **AI 환각 방지** — 원문 컨텍스트 한정 분석으로 신뢰성 확보.
  3. **무료·간편** — 보험 선택/약관 업로드만으로 즉시 분석.
- 각 카드: lucide 아이콘 + 제목 + 한 줄 설명. 반응형(모바일 1열, sm+ 3열).

### LandingFooter
- 서비스명(보장zip) + 간단한 링크 묶음 + 면책 문구 + 카피라이트. 정적 컴포넌트.

## 데이터 흐름

- 랜딩은 백엔드 API를 호출하지 않는다(정적 마케팅 페이지). 시나리오 텍스트 등은 프론트 로컬 데이터.
- CTA → `/home` 라우트 이동만 수행. 인증/케이스 생성은 기존 홈 흐름이 담당.

## 에러 처리

- 외부 I/O가 없으므로 런타임 에러 표면은 작다. 애니메이션 타이머는 언마운트 시 정리(cleanup)한다.

## 테스트 / 검증

- 타입체크/린트: `cd frontend && pnpm lint && pnpm build` 통과(CI 기준).
- 수동 확인: `/` 진입 시 랜딩 표시, CTA가 `/home`으로 이동, 로테이트/타자기/마퀴 동작,
  `prefers-reduced-motion`에서 애니메이션 정지.
- 반응형: 모바일/데스크톱 레이아웃 확인.

## 범위 밖 (YAGNI)

- 최종 CTA 배너, FAQ 아코디언, 이용 단계 요약 섹션.
- 실제 스크린샷/영상, 백엔드 연동, 다국어.
