# 질병군 매핑 레이어 설계

## 정의

`질병코드 -> 약관 특약` 사이에 `질병군` 레이어를 하나 추가한다.

사용자 입력을 바로 약관명과 맞추는 구조가 아니라 아래처럼 처리한다.

```text
사용자 입력
-> 질병명/치료상황 추출
-> 질병코드 후보 추출
-> 질병군 후보 분류
-> 특약별 지급조건 매칭
-> 사용자에게 쉬운 말로 확인
```

예시:

```text
허리디스크로 통원치료 받았어요
-> 질병명: 허리디스크
-> KCD 후보: M51
-> 질병군: 디스크질환, 일반질병
-> 치료상황: 통원
-> 매칭 후보: 질병 실손 통원, 질병비급여 통원, 3대비급여 MRI/도수치료 등
```

## 질병군이 필요한 경우

질병군이 반드시 필요한 경우는 약관이 특정 질병명 또는 질병 분류표를 지급조건으로 쓰는 경우다.

필요:

- 암진단비, 유사암진단비, 갑상선암진단비, 특정암진단비
- 암수술비, 항암치료비, 암입원/통원일당처럼 암 진단이 선행조건인 보장
- 뇌혈관질환, 뇌졸중, 뇌출혈, 허혈심장질환, 급성심근경색증 보장
- 2대질병, 3대질병, 26대/37대 생활습관병, 116대질병수술비
- 당뇨, 대상포진, 통풍, 백내장 등 특정 질병 보장
- 골절, 화상, 특정상해처럼 약관 별표의 상해분류표를 쓰는 보장
- 면책조항이 특정 KCD 범위를 제외하는 경우

보조로만 필요한 경우:

- 실손 입원/통원 보장
- 일반 질병입원일당
- 일반 질병수술비
- 일반 상해입원일당
- 응급실내원비
- 깁스치료비
- MRI/CT/도수/주사료 등 치료행위 중심 보장

이 경우는 질병코드보다 `질병/상해`, `입원/통원`, `급여/비급여`, `치료행위`, `결제금액`이 더 중요하다.

불필요하거나 낮은 경우:

- 무사고축하금
- 자동차사고 부상등급처럼 KCD가 아니라 사고 등급표가 기준인 보장
- 순수 사망/후유장해 보장 중 질병명이 지급조건이 아닌 경우

## 첨부 약관 기준 판단 결과

첨부된 6개 JSON 특약 391개를 기준으로 보면 다음처럼 나뉜다.

| 구분 | 건수 | 의미 |
|---|---:|---|
| 질병군 필요 | 253 | 암, 뇌/심장, 특정질병, 골절/화상처럼 질병군 또는 분류표가 지급조건 |
| 질병군 보조 | 113 | 실손, 입원, 수술, 통원처럼 치료상황이 우선이고 질병군은 보조정보 |
| 불필요/낮음 | 25 | 무사고, 등급표, 일반 사고조건 등 질병군 매칭 영향 낮음 |

보험별로는 암보험과 3대질병보험에서 질병군 필요 비중이 높고, 실손보험은 전부 보조로 보면 된다.

## 추천 DB 구조

기존 테이블은 유지하고 아래 4개를 추가한다.

```text
disease_groups
질병군 마스터. 예: 일반암, 유사암, 갑상선암, 뇌혈관질환, 허혈심장질환

disease_group_code_rules
질병군에 속하는 KCD 코드 범위. 예: 갑상선암 -> C73

disease_group_aliases
사용자 표현/약관 표현 별칭. 예: 허리디스크 -> 디스크질환, 추간판장애

rider_disease_rules
특약이 요구하거나 제외하는 질병군. 예: 암진단비(유사암제외) -> 일반암 포함, 유사암 제외
```

`cases`에는 확정 코드 하나만 두기보다 후보를 남기는 필드를 추가하는 것이 좋다.

```text
disease_kcd            대표 후보 코드
disease_kcd_candidates 후보 코드 배열
disease_group_candidates 후보 질병군 배열
```

## 매칭 원칙

### 1. 질병군 필수 특약

특약명이나 지급조건에 아래 표현이 있으면 질병군 매핑을 필수로 건다.

```text
암, 유사암, 갑상선암, 기타피부암, 제자리암, 경계성종양,
뇌혈관질환, 뇌졸중, 뇌출혈,
허혈심장질환, 급성심근경색증,
생활습관병, 당뇨, 대상포진, 통풍, 백내장,
골절, 화상, 동상, 특정상해
```

### 2. 치료상황 우선 특약

아래 특약은 질병군보다 치료상황을 먼저 본다.

```text
실손, 입원일당, 통원, 수술비, 응급실, 깁스, MRI, CT, 도수치료, 주사료
```

예시:

```text
허리디스크 + 통원 + 8만원 결제
-> 질병군은 디스크질환/일반질병
-> 하지만 실제 매칭은 질병 실손 통원, 비급여 통원, 3대비급여 여부 중심
```

### 3. 질병군과 치료상황을 둘 다 봐야 하는 특약

암수술비, 암입원일당, 뇌혈관질환입원일당, 허혈심장질환수술비처럼 `질병군 + 치료행위`가 모두 필요한 특약이다.

예시:

```text
갑상선암 + 수술
-> 질병군: 갑상선암/유사암
-> 치료상황: 수술
-> 매칭: 갑상선암진단비, 유사암수술비, 암수술비(유사암포함 여부 확인)
```

## UI 표현

사용자에게는 질병코드나 질병군을 앞세우지 않는다.

권장:

```text
입력하신 내용을 디스크 관련 질환으로 분류했어요.
이 기준으로 약관을 확인할게요.
```

비권장:

```text
M51 기타 추간판장애 후보입니다.
정확한 KCD 코드를 확인해주세요.
```

후보가 여러 개인 경우:

```text
비슷한 표현이 여러 가지로 분류될 수 있어요.
병원에서 들은 내용에 가장 가까운 걸 골라주세요.

- 허리디스크
- 목디스크
- 단순 허리통증
- 허리 삐끗함/염좌
- 잘 모르겠음
```

## 구현 흐름

```text
1. 챗봇이 사용자 문장에서 질병명, 치료상황, 결제정보를 추출한다.
2. diseases.search_text에서 질병코드 후보를 찾는다.
3. disease_group_code_rules와 disease_group_aliases로 질병군 후보를 만든다.
4. rider_disease_rules가 있는 특약은 질병군 포함/제외 조건을 먼저 본다.
5. 나머지 특약은 trigger_type, claim_rule, 입원/통원/수술/급여/비급여 조건으로 본다.
6. 후보가 애매하면 코드가 아니라 쉬운 질문으로 확인한다.
7. 결과 화면에는 "입력 내용 기준 예상"과 "실제 진단서와 다를 수 있음"을 표시한다.
```

## 주의점

- 질병군 코드는 반드시 약관 별표 기준으로 최종 검수해야 한다.
- `diseases.csv`는 사용자 표현을 KCD 후보로 바꾸는 데 좋지만, 약관의 보장범위를 완전히 대체하지는 않는다.
- 보험사마다 "암", "유사암", "특정소액암", "중증갑상선암" 정의가 다를 수 있으므로 `rider_disease_rules`는 policy/rider 단위로 오버라이드 가능하게 둔다.
- AI는 질병코드를 확정하지 않고 후보를 분류한다. 확정 표현은 피한다.
